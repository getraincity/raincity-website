## 2. Google Maps Issue

### Diagnosis

All three map embeds on the site (homepage quote form, `/locations` coverage map, each `/locations/[slug]` community map) were using the legacy Google Maps embed URL:

```
https://maps.google.com/maps?q=QUERY&z=ZOOM&output=embed
```

Google deprecated this free legacy embed URL for new usage in 2018. It now shows a **"For development purposes only"** watermark or a **"This page can't load Google Maps correctly"** error on many deployments. The site is not using the Maps JavaScript API — it is using iframe embeds only — but the legacy iframe URL itself has been phased out.

### What was fixed at the code level

All three iframe components have been updated to use the **Maps Embed API** URL format, which is the current supported approach:

| Component | File |
|---|---|
| Homepage quote form map | `components/home/QuoteForm.tsx` |
| /locations coverage map | `components/locations/CoverageMap.tsx` |
| /locations/[slug] community maps | `components/location/LocationMap.tsx` |

The new URL format for each map:
```
https://www.google.com/maps/embed/v1/place?key=YOUR_KEY&q=QUERY&zoom=N
```

The API key is read from the environment variable `NEXT_PUBLIC_GOOGLE_MAPS_KEY`. If the key is not set, each map panel renders a clean text fallback (e.g. "Based in New Westminster, serving Greater Vancouver") rather than an error iframe.

The Content-Security-Policy `frame-src` directive in `next.config.ts` has been updated to allow `https://www.google.com` (the Maps Embed API domain) in addition to the existing `https://maps.google.com`.

The `.env.local.example` file has been updated with step-by-step instructions for obtaining and configuring the key.

### What still needs to be done on Google Cloud Console

The Maps Embed API requires an active Google Cloud billing account and a valid API key. These cannot be configured from the codebase. You must:

1. **Go to** https://console.cloud.google.com and select your project (or create one for this site).
2. **Enable the Maps Embed API:** APIs & Services → Library → search "Maps Embed API" → Enable.
3. **Confirm billing is active:** Billing menu — the Maps Embed API requires a billing account attached to the project. The free tier ($200/month credit) covers thousands of map loads; this site will not exceed it.
4. **Create an API key:** APIs & Services → Credentials → Create Credentials → API Key.
5. **Restrict the key (important — prevents abuse):**
   - Application restrictions → HTTP referrers → add `raincitypms.com/*`
   - API restrictions → Restrict key → select "Maps Embed API" only
6. **Copy the key** into your `.env.local` file:
   ```
   NEXT_PUBLIC_GOOGLE_MAPS_KEY=AIza...
   ```
7. **Rebuild and redeploy** — the key is embedded at build time (`NEXT_PUBLIC_` prefix).

## 3. Search Console Readiness Checklist

### sitemap.xml — PASS

Generated by `app/sitemap.ts` from the live content arrays (`services`, `locations`, `blogPosts`, `legalPages`). Lists 36 URLs. Every URL in the sitemap resolves to a real built page. No broken or placeholder entries.

Note: Six blog posts and nine location pages appear in the sitemap while carrying `noindex` on their routes. This is intentional (see noindex section below) — a URL in the sitemap and a noindex directive on the route are not mutually exclusive; the sitemap signals "this URL exists and resolves," and the noindex signals "do not add it to the index yet." Google will crawl but not index them until the directive is removed.

### robots.txt — PASS

Generated by `app/robots.ts`. Allows all user agents at `/`, disallows `/_next/` (framework internals) and `/api/` (form endpoint). Googlebot is explicitly invited. All major AI crawlers (GPTBot, ClaudeBot, PerplexityBot, Google-Extended, etc.) are also explicitly listed and allowed, which is correct for this site.

### Canonical tags — PASS

Every page calls `pageMetadata({ path: "/..." })` which sets `alternates.canonical` to the absolute production URL via the `canonical()` helper in `lib/seo.tsx`. Next.js renders this as `<link rel="canonical" href="https://raincitypms.com/...">`. No page is missing a canonical tag, and no page points its canonical at a different page.

### noindex status — INTENTIONAL / ACTION REQUIRED BEFORE FULL LAUNCH

Several groups of pages carry `robots: { index: false, follow: true }` — meaning Google will crawl them but not add them to the index. This is intentional in every case because the content at those URLs is placeholder copy that has not been confirmed by the client. The noindex must be **removed route-by-route once the content is ready**, not globally.

| Route | noindex reason | Action to remove |
|---|---|---|
| `/blog` | Placeholder blog content | Replace all six posts with real content; client confirms |
| `/blog/[slug]` (6 posts) | Placeholder blog content | Same as above |
| `/blog/page/[page]` | Archive pager | Lift with the blog index once real posts are live |
| `/locations/[slug]` (9 pages) | Per-community copy unconfirmed | Client reviews and confirms `detail` block in `lib/content.ts` for each community |
| `/terms` | Placeholder legal text — unreviewed | Legal review completed and signed off |
| `/privacy-policy` | Placeholder legal text — unreviewed | Legal review completed and signed off |

To remove noindex from a route, delete the `robots: { index: false, follow: true }` line from its `metadata` export in the corresponding `app/.../page.tsx` file.

### Duplicate title tags — PASS

Every page calls `pageMetadata` with a unique, fully-written title. `{ absolute: title }` opts out of the layout's `%s | RainCity Property Maintenance` template, so no page inherits the default. No two pages share a title.

### Duplicate meta descriptions — PASS

Every page supplies its own description to `pageMetadata`. No generic fallback is possible given how the function is typed. No duplicates detected.

### Broken internal links — PASS

The build prerenders 39 pages. Every `<Link href="...">` in the codebase points at a route that exists in the build. The four footer social links are placeholder `"#"` hrefs — these need real URLs before launch but they are not internal page links and do not affect crawl.

### Status codes — PASS

All 37 public routes return 200. Two permanent redirects are in place:

### Mixed content — PASS

Every resource (photographs, fonts, scripts, styles) is self-hosted from the same origin. `next.config.ts` declares no `remotePatterns`, so no external image CDN is in the loading path. Google Maps iframes load from `https://www.google.com` after the fix above. No HTTP resources are loaded from an HTTPS page.
